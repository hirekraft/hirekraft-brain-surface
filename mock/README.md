# /mock/ — DEAD END. Not a build path, not a surface.

**Stopped 2026-09-09. Do not resume from these files.**

This directory holds exactly one file, `index.html`, which is round one — and the
only round — of a throwaway mockup pass for a proposed Tool shell. The pass ended
the day it was delivered, because the direction changed: **the studio is staying on
the current Tool surface and testing it, rather than reshaping it.**

## What this is not

- **Not a build path.** Nothing here is scheduled to be built.
- **Not a surface.** It holds no data, calls nothing, and imports nothing from any
  deployed file. It is reachable only by typing its URL; no door anywhere points
  at it.
- **Not specified.** The type scale, palette, room names, copy and the eight
  screens are one unreviewed round. None of it was accepted. Treating any of it as
  a decision would be reading a sketch as a spec.

## The question in it was withdrawn, not left open

The mock deliberately contains two versions of the cold-start screen, because the
choice between them — go straight to connecting a source, or let a person ask
questions of a sample business first — was the fork the round existed to put in
front of Alex. **It was never answered, and it is not pending.** The question was
withdrawn with the pass.

## Why this file exists

This estate has twice ended up with two live surfaces because something was retired
in intent and never in fact, and a third instance is in this repository right now
(the root `index.html`, the old Command Center, whose door was removed while the
page stayed). A directory of plausible-looking screens with no note is exactly how
a later seat concludes a shell redesign was in flight and picks it back up.

## If the shell work ever does resume

**Start from the feedback, not from these files.** Round one drew five specific
criticisms, all recorded in the snapshot that closed the seat:

1. Content constrained to a narrow column inside very wide cards, so the text reads
   cramped while the cards read empty.
2. The rail is nearly empty on the cold start, where it would do real work showing
   the rooms greyed out and unavailable — so a person can see what the thing will
   become.
3. No ask element anywhere on the cold start, not even a disabled placeholder, on
   the one screen where a customer first meets the product.
4. Books is presented identically to Mail and Drive despite being account-shaped
   with no per-person boundary — which the locked spec says must be stated at the
   connect moment, not discovered later.
5. "Start with one" followed by three equal options, which restates the cold-start
   problem rather than solving it.

Also unresolved: the mock carried a tap counter meant to settle whether People and
Calendar are real rooms or should be a filter and a piece of context. **It never
ran.** That question goes back to being settled by real use of the real surface.
